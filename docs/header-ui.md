# Header UI rendering (Svelte 5)

`JournalHeaderFeature.load` registers a `journal-header` code block processor. For each occurrence:

1. Resolve settings for the current file (with the code block body as embedded config).
2. Build a `JournalNote` via the factory.
3. `buildJournalHeaderInfo(settings, note)` produces a plain `JournalHeaderInfo` containing the title, `backwardLink` / `forwardLink` / `todayLink` chips for the primary row, plus `moreLinks` (higher-order period chips, label always `'Jump to'`), `secondaryLinks` (primary lower-order period entries — months for yearly, weeks for monthly, days for weekly), and `extraLinks` (an optional supplementary section, currently only populated with the four overlapping quarters on a yearly note when `quartersEnabled` is on). Each list ships with its own label field.
4. `mount(JournalHeader, { target: el, props: { info, note, confirmCreate, navigate, defaultCalendarVisible } })` — Svelte 5 `mount` API, components use runes (`$props()`). The feature also constructs a `confirmCreate` (opens the `ConfirmCreateModal`) and a `navigate` callback (`workspace.openLinkText`) so the calendar can intercept clicks on past-missing cells without losing native link behavior elsewhere.

Errors are caught and rendered via the `ErrorMessage.svelte` component instead of being thrown.

## Primary row and the More popover

The primary row shows only `back ‹‹ More... · Today · ›› forward`. **Today-fold:** when the previous or next sibling resolves to today's daily note, that arrow's chip is relabelled `Today` (`linkWithTitlePattern('[Today]')` on the resolved target) and the standalone Today button is dropped — it would point to the same note. The target resolution that decides this is shared with the chip builders: `resolveForwardTarget` / `resolveBackwardTarget` return the `JournalNote` the arrow points at (direct sibling when present/future-or-existing, else `closestSibling`), and `buildTodayLink(mergedIntoArrow)` returns `undefined` when either the host *is* today or `backwardIsToday || forwardIsToday`. Everything else lives in the **More popover**, which renders up to three sections — in this order: **Jump to** (`moreLinks`), the primary lower-order section (`secondaryLinks`, labelled `Day`/`Week`/`Month`/`Year` per `labelFor(unit)`), and **Quarter** (`extraLinks`, only on yearly notes when quarters are enabled). Each section is fully conditional: empty sections collapse out entirely. The "Show calendar" / "Hide calendar" toggle lives in the section header of whichever section is **first** at render time — Jump to when it's non-empty, otherwise the primary lower-order section, otherwise the Quarter section. The two `JournalHeader.svelte` snippets (`calendarToggle` and `section`) keep the markup factored. The popover is **portaled to `document.body`** when open and positioned with `getBoundingClientRect()` on the options bar; this is intentional — in live-preview mode the CodeMirror widget wrapping the code block clips absolutely-positioned descendants, so the panel has to escape the widget's containing block. Repositioning runs on window resize and on capture-phase `scroll` events (the editor pane scrolls separately from the window).

### Spanning-tier rule for `moreLinks`

`buildMoreLinks` groups higher-order entries by tier (consecutive same-`timeUnit` results from `getHigherOrderNotes()`). When a tier returns **two** entries — a week that crosses a quarter or month boundary, for example — both are emitted, with past+missing entries flagged `needsConfirmation: true` (the secondary list's convention) so the boundary-crossing relationship is always visible. When a tier returns one entry, the existing `isExistingNote() || isPresentOrFuture()` filter still applies so an unspanning past note doesn't show a long tail of past-missing containers. Net effect: `2026-W14` on a today of `2026-05-03` shows `[2026, 2026 Q1 (faded, prompts on click), 2026 Q2, March 2026 (faded, prompts on click), April 2026 (faded, prompts on click)]` instead of just `[2026, 2026 Q2]`.

Because the panel is portaled out of the markdown render container, Obsidian's `.internal-link` click interception no longer fires on its links (that handler is scoped to the rendered markdown). The panel installs its own delegated `onclick` that uses `findInternalLinkHref` (in `internal-link-target.ts`) to walk up to the nearest `<a class="internal-link">`, then closes the popover and routes the href through the injected `navigate` callback. Primary-row chips don't need this delegation: they stay inside the rendered markdown container where Obsidian's handler still fires.

### Past-missing links and the create-confirmation flow

`Link.needsConfirmation` (set on every past+missing entry across `moreLinks`, `secondaryLinks`, and `extraLinks`) is the same flag the calendar uses on past-missing cells, with the same UX: the link still renders — clickable and faded with the past-missing opacity (`calc(var(--link-unresolved-opacity, 0.7) * 0.5)`) — but clicking it routes through `confirmCreateNote` (an Obsidian `Modal` resolving a `Promise<boolean>`) rather than Obsidian's default open-or-create flow. On confirm we navigate via the injected `navigate` callback; on cancel nothing happens. This gives the user the same "I can create any past note from anywhere" affordance the calendar already had — the More panel's higher-order chain, primary lower-order list, and Quarter section all now offer it for days/weeks/months/quarters/years.

`NoteLink.svelte` owns the click interception for past-missing entries (it preventDefaults+stopPropagations the click before it bubbles, so the panel's delegated handler doesn't double-fire `navigate`). Plain (existing or future-missing) entries skip the interception so the panel handler / Obsidian handler can take over. `JournalHeader.svelte` threads `confirmCreate` and `navigate` (built in `journal-header-feature.ts`) through to every `NoteLink` instance — primary-row chips and panel links alike — and panel links additionally get `onAfterClick={closeMore}` so the popover closes once the user has committed or cancelled. Primary-row chips don't currently surface past-missing links (the `createBackwardLink`/`createForwardLink` logic falls back to `closestSibling` when the direct sibling is past+missing), but the wiring is in place so any future entry point that does emit one will get the confirmation flow for free.

## Secondary list patterns

Secondary list date patterns are derived from the lower-order `timeUnit` and use non-breaking spaces; they intentionally drop the year because the H1 already shows it. Don't reach for the user-configured `titlePattern`/`shortTitlePattern` for these — see `secondaryTitlePatternFor` in `journal-header-info.ts`. The same `secondaryTitlePatternFor` powers the Quarter `extraLinks` rendering on yearly notes (`[Q]Q` → `Q1`/`Q2`/…).
