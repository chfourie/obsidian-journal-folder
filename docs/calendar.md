# Calendar picker

`JournalCalendar.svelte` renders below the options bar inside the same sticky header when `calendarVisible` is true. The pure model lives in `journal-calendar-info.ts` (`buildCalendarInfo(note, { visibleMonthCount, offsetMonths })`) and is fully unit-tested — it owns no DOM or IO. Per month: clickable `MMM` + `YYYY` title (plus a `(Q1)`–`(Q4)` quarter chip when `note.hasUnit('quarter')`, linking to the corresponding `YYYY-Q[1-4]` note), weekday header row, locale week-number column on the left, and a 6×7 day grid (rows that are entirely outside-month are skipped, and individual outside-month days inside otherwise-populated rows are rendered as empty placeholders). Default month-window placement is right-biased: `monthsBefore = floor(N/2)`.

## Visible month count

The component measures its container with a ResizeObserver and feeds the width into `pickVisibleMonthCount(width, { isMobile })` (in `visible-month-count.ts`, capped at `MAX_MONTHS = 5`); desktop uses 213px per slot, mobile 333px — both bake in the inter-month gap so `floor(available / minMonthPx)` slightly *over*-reserves rather than under-reserves, preventing the picker from returning a count whose fixed-width grids would overflow their containers. 213 is the smallest value that keeps the simple formula safe for all `N <= MAX_MONTHS` and was chosen so 3 calendars fit in Obsidian's default readable-line-length content area (~696px); going higher (e.g. the previous 220) would force the picker to drop to 2 at the default width even though 3 actually fit. Each `.journal-folder-calendar-month` is `flex-shrink: 0` for the same reason: the cells inside don't shrink, so the month container must not shrink either, otherwise the grid would visually leak into the next month. Arrow buttons (using Obsidian's `clickable-icon` class for theme conformance) shift `offsetMonths` by ±1.

## Quick-navigation strip and date picker

Above the months grid sits a controls row with two link-styled spans: **Today** (sets `offsetMonths` so today's calendar month sits at the anchor — a no-op when viewing today's daily note, scrolls to today otherwise) and **{Month} {Year}** (e.g. `May 2026`) — the second one toggles a date-picker popover. They're `<span role="button" tabindex="0">` rather than `<button>` because Obsidian's stylesheet repaints native buttons with a filled chip background; spans bypass it so the controls render as plain underlined accent text. An `onKey` factory wraps each handler so Enter/Space activate them like a real button.

The popover is portaled to `<body>` for the same reason the More popover is — CodeMirror live-preview widgets clip absolutely-positioned descendants — and contains a year row (`‹ 2026 ›` with `clickable-icon` chevrons that shift `offsetMonths` by ±12) plus a 4×3 grid of locale short month names. Year chevrons live-update the calendar (the centred year label tracks `centeredAnchor.year`); clicking a month commits via `offsetForTarget(noteMoment, centeredAnchor.year, value)` and closes the popover. The centred month is bolded in the grid. Positioning centres the popover horizontally on the trigger via `getBoundingClientRect()` and clamps to within 8px of either viewport edge so it can't overflow; resize and capture-phase scroll re-run the same logic.

Pure helpers for the controls/picker live in `calendar-navigation.ts` (unit-tested in isolation): `anchorMonth(noteMoment, offsetMonths)` returns the `{year, month}` at the anchor index, `offsetForTarget(noteMoment, year, month)` is its inverse (used by Today and the month grid), and `monthOptions()` produces locale-aware short month names via Obsidian's bundled moment.

Desktop picker uses ~1/3 the padding/gap of mobile — `.journal-folder-calendar-picker.is-mobile` overrides restore the roomier mobile spacing. Font sizes (1rem month, 1.1rem year label, 1.4rem chevron) and the month cells' `min-height: 2.75rem` are shared across platforms so the grid's row-to-row breathing room and type sizes stay consistent; the year-arrow's `width: 2.75rem; min-height: 2.75rem` tap-target sizing is mobile-only so the year row collapses to its content height on desktop, which is what tightens the year-to-grid gap (the picker's flex `gap` is also halved on desktop, but the visible reduction came from the year row, not the gap). The user iterated on this — first wanting mobile spacing on desktop, then walking it back to 1/3, then asking for desktop year-to-grid spacing specifically without touching inter-row spacing — so the current state is "rows breathe the same on both platforms, but the year row hugs the grid on desktop". The options-row's `margin-bottom: 1rem` is halved to `.5rem` via `.journal-folder-header-options:has(+ .journal-folder-calendar)` when the calendar is visible, pulling the controls strip closer to the More-row above without changing the spacing when the calendar is hidden.

## Mobile vs desktop

Mobile vs desktop is decided at mount time from `Platform.isMobile` (Obsidian's runtime constant) and threaded as an `isMobile` prop down through `JournalHeader` to the calendar; the calendar applies a `.is-mobile` class on its root and CSS scopes the enlarged cell sizing under that class so desktop styling stays exactly as it was.

## Day cells and divider grid

Day cells use a fixed track width — `1.32rem` on desktop, `1.8rem` on mobile — rather than the original `1fr` or a `minmax(0, …)` cap. Fixing the width keeps the column spacing identical regardless of how much pane room each month gets, which the user wanted after seeing cells stretch and shrink as `pickVisibleMonthCount` swapped between 1-up and N-up layouts. Months are slightly wider than `pickVisibleMonthCount`'s `DESKTOP_MIN_MONTH_PX = 180`, so in extremely narrow editors a calendar can horizontally overflow its month container — acceptable trade for visually consistent column spacing across all configurations. A 1px vertical divider sits between the week-number column and the weekday columns via a dedicated `.35rem`-wide grid track (`.5rem` on mobile) containing a centred `.journal-folder-calendar-divider` element that spans `grid-row: 1 / -1`. The divider only resolves correctly if the grid has an *explicit* row template (otherwise `-1` collapses to `1` and auto-flow leaks day cells into column 2 on subsequent rows), so `JournalCalendar.svelte` computes `renderedWeekCount` per month and writes `grid-template-rows: repeat(renderedWeekCount + 1, auto)` as an inline style — the count must be exact rather than a static `repeat(7, …)` because the trailing `row-gap: 1px` would otherwise leave 1–2px of phantom space below short months. The `.journal-folder-calendar-months` container uses `display: flex; justify-content: center` rather than equal-share grid columns so the visible months cluster in the middle of the pane instead of fanning out across the full width when fewer months are shown than would fit.

## Cell classes and unresolved-link styling

Cell classes are stamped by `calendarCellClasses` in `calendar-cell-classes.ts` (extracted from the Svelte component so it's unit-testable) and crucially the `is-unresolved` decision is made from the plugin's own `cell.exists` rather than left to Obsidian's link-resolution pass. Obsidian only stamps `is-unresolved` on internal-link cells present during the initial markdown render — but the calendar progressively inserts months as the ResizeObserver settles (initial `measuredWidth = 0` yields a `visibleMonthCount` of 1, then a real measurement bumps it up) and arrow-scroll inserts new months on demand. Cells inserted after the post-processor returns never get Obsidian's stamp, so missing cells in those months would render at full opacity while missing cells in the initially-rendered month would render at the theme's reduced unresolved-link opacity — visually inconsistent across months. Stamping the class ourselves makes the behaviour uniform regardless of insertion timing.

The base cell colour is `var(--text-normal) !important` — the `!important` is essential because many community themes (and Obsidian itself) restyle `a.internal-link.is-unresolved` in the accent colour or a custom red, which would otherwise leak through onto every missing day in the calendar. We deliberately do *not* want the calendar to inherit Obsidian's link-coloring decisions — only colour control sits with us; the theme controls colour through `--text-normal` (its normal text colour) and through `--text-accent` (used for existing cells and Sundays). The opacity for missing cells *does* still come from the theme via `--link-unresolved-opacity` because there's no `opacity: !important` on the base, so themes still get to decide how faded an unresolved link looks.

The full styling hierarchy: future-missing → `--text-normal` at the theme's `--link-unresolved-opacity` (faded but normal-coloured); past-missing → same colour but with extra opacity reduction (`calc(var(--link-unresolved-opacity, 0.7) * 0.5) !important`) so it reads as 50% more faded (the multiplier was tuned by eye — 0.8/20% and 0.7/30% weren't pronounced enough at the small calendar cell sizes; the `!important` is required because Obsidian's `a.internal-link.is-unresolved` opacity rule at specificity (0,2,1) outranks our selector at (0,2,0)) — CSS `opacity` doesn't multiply across classes on the same element so the combined value is restated rather than layered on top of `is-unresolved`'s declaration; existing → `--text-accent !important` + bold + underlined; today gets an accent ring; the cell that exactly matches the open note gets the accent fill.

Sundays are an orthogonal accent override: `buildDayCell` flags day cells with `isSunday` (week/month/year cells always set it false), `buildWeekdayHeaders` returns `{ label, isSunday }` so the Sunday weekday-label also gets `--text-accent`, and `calendarCellClasses` stamps `is-sunday` on day cells so `.journal-folder-calendar-cell.day.is-sunday` repaints Sunday day cells in `--text-accent !important` (the `!important` is required because the base rule already uses `!important` to lock missing cells to `--text-normal`). The unresolved opacity (and the past-missing fade) still applies on top, so a past-missing Sunday is accent-coloured but faded.

Past-missing clicks are intercepted via `event.preventDefault()` + an Obsidian `Modal` (see `confirm-create-modal.ts`) that resolves a `Promise<boolean>`; on confirm we navigate manually via the injected `navigate` callback (Obsidian's link interception is async-incompatible).

## Visibility store and platform-specific defaults

Visibility is shared via a Svelte writable in `calendar-visibility.ts`. The store is in-memory only (resets on Obsidian restart). Default visibility is split across two independent settings — `defaultCalendarVisibleDesktop` (default `true`) and `defaultCalendarVisibleMobile` (default `false`) — because the calendar's multi-month layout isn't useful at phone widths so suppressing it by default on mobile is the common case. `resolveDefaultCalendarVisible(settings, isMobile)` in `resolve-default-calendar-visible.ts` picks the platform-appropriate field (no fallback between them) and coerces it via `isTruthy` so the literal string `"false"` from embedded `key: value` configs is honored as false (front-matter values arrive as real YAML booleans and don't need this). The platform decision uses `Platform.isMobile` (Obsidian's runtime constant), made in `journal-header-feature.ts`. The resolved value flows through the standard 3-layer resolution before the platform pick; both fields can be overridden per-folder via `default-calendar-visible-desktop` / `default-calendar-visible-mobile` keys in `journal-folder.md` front matter or in an embedded header config block. On each header mount, `applyCalendarDefault(value)` syncs the store to the resolved default — but a session-scoped `userHasToggled` flag, set the first time the user clicks the toggle, makes `applyCalendarDefault` a no-op for the rest of the session so navigating between folders with different defaults doesn't override an explicit user choice.
